- Add `MethodBodyPatching` for runtimes that replace method bodies themselves. A host registers an eligibility check, a baseline reader and an installer. Harmony then exports each patched body, and the host installs it. A patch on an open generic definition applies to every instantiation. Ordinary runtimes keep the MonoMod detour.
- Add `CodeMatch.GetsProperty` and `CodeMatch.SetsProperty` to match calls to a property's getter or setter ([#790](https://github.com/pardeike/Harmony/issues/790)). `SymbolExtensions.GetPropertyInfo` returns the property from a lambda.
- Reject a transpiler that jumps to a label that no instruction carries. Before, such a jump could go to the start of the method and loop forever. The error names the transpilers.
- The stack depth error now names both depths and the transpilers. Validation stays on by default. For a runtime that accepts such IL, `Harmony.ValidateStack = false` or the environment variable `HARMONY_VALIDATE_STACK=0` leaves the check to the runtime.
- Fix `AccessTools.IsNetCoreRuntime`, which was false on every runtime. `AccessTools.IsNetFrameworkRuntime` is no longer true on .NET Core 3.x.
- Fix the `InvalidOperationException` that the .NET 11 compile watch threw when a `DynamicMethod` was compiled ([#788](https://github.com/pardeike/Harmony/issues/788)).
- Document every public member. The API reference now builds from the net48 assembly, so it includes `MethodType.Async` and `AccessTools.AsyncMoveNext`.
- Known issue on .NET 11, unchanged from rc.4: callers compiled with runtime-async, including the .NET 11 runtime libraries, call the async variant of an ordinary `Task`-returning method, which a patch does not reach. With the embedded MonoMod, a variant compiled after the patch corrupts code and can crash the process ([MonoMod#344](https://github.com/MonoMod/MonoMod/issues/344)). Harmony logs the bypass when `Harmony.DEBUG` is on.
