- Fix stale `__args` in ordinary patches ([#792](https://github.com/pardeike/Harmony/pull/792)). Each patch that takes `__args` now gets the current argument values, including writes from earlier patches and from the original. Before, a patch that only read `__args` could undo an earlier `ref` write or the original's `ref` and `out` results.
- Behavior change: a `ref object` parameter bound to a value-type argument passed by value now writes back to that argument. Harmony 2 discarded the write. The box must hold the argument's own type, because Harmony does not convert numbers. For a `long` argument, `value = 17` throws `InvalidCastException`. Write `value = 17L`. `__args` and arguments passed by reference already follow this rule.
- Support the .NET 11 release ([#785](https://github.com/pardeike/Harmony/issues/785)). Earlier candidates were built and tested with RC3.
- Add `MethodType` members for the unsigned right shift operator, the checked operators and the compound assignment operators ([#791](https://github.com/pardeike/Harmony/issues/791)).
- Embed MonoMod.Core 1.4.0-prerelease.2. On .NET 11, a patch on an ordinary `Task`-returning method now reaches callers compiled with runtime-async. The known issue from rc.4 and rc.5 no longer occurs in Harmony's tests on x64 and ARM64 ([MonoMod#344](https://github.com/MonoMod/MonoMod/issues/344)).
- New limit on .NET 11: MonoMod refuses to detour a generic method instantiation such as `Method<int>()`, and `Harmony.Patch` throws `NotSupportedException`. A non-generic method of a generic class is not affected.
- Lib.Harmony.Thin no longer ships the build workaround for MonoMod's .NET 11 guard.
